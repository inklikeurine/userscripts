# AGENTS.md

Instructions for AI agents (and humans) working in this repository.

## What this repo is

A collection of browser userscripts generated by AI. Every script here was
written by an AI agent under human direction. Users of these scripts do so at
their own risk.

**Firefox only.** All scripts are developed and tested in Firefox exclusively.
Chrome and other browsers are not used, not tested, and not supported.

**Violentmonkey only.** Scripts target
[Violentmonkey](https://violentmonkey.github.io/) as the userscript manager.
Tampermonkey and Greasemonkey are not tested and not supported; do not write
code paths to accommodate them.

## Hosting and URLs

The repository is hosted on GitHub at
`https://github.com/inklikeurine/userscripts`. Every URL in a script or README
derives from that; never invent a different host or path shape.

| Purpose | Value |
|---|---|
| `@namespace` (every script, identical) | `https://github.com/inklikeurine/userscripts` |
| `@homepageURL` | `https://github.com/inklikeurine/userscripts/tree/main/<website>/<script-name>` |
| `@supportURL` | `https://github.com/inklikeurine/userscripts/issues` |
| `@downloadURL` and `@updateURL` (identical) | `https://raw.githubusercontent.com/inklikeurine/userscripts/main/<website>/<script-name>/<script-name>.user.js` |
| README "Install" link | the same raw URL as `@downloadURL` |

Managers key an installed script on `@namespace` + `@name`, so the namespace
is one fixed string for the whole repo. Managers only check for updates when
`@downloadURL`/`@updateURL` are present — without them a version bump never
reaches anyone.

## Required repo-level files

These files must always exist at the repo root. If one is missing, create it
before doing anything else.

### `README.md`

Must contain, in this order:

1. A statement that this is a repository of AI-generated userscripts and that
   they are provided as-is, **use at your own risk**.
2. A statement that scripts are **tested in Firefox only**, with
   **Violentmonkey** as the only supported userscript manager.
3. A **Userscripts** section listing every script in the repo, grouped by
   website. Each website gets a sub-heading; under it, a bulleted list of that
   site's scripts, each linking to the script's folder with a one-line
   description. This list must be kept in sync with the folders that actually
   exist — adding, renaming, or removing a script means updating this list in
   the same change. While the repo has no scripts the section holds the single
   line `_No scripts yet._`; remove it when the first script lands.
4. A short **License** section pointing to `UNLICENSE`.

### `UNLICENSE`

The verbatim text of the Unlicense (<https://unlicense.org>). This code is
AI-generated and the maintainers consider it unlicensable; the Unlicense
releases it into the public domain to the fullest extent possible. Do not
replace it with any other license and do not add license headers to scripts.

## Repo layout

Scripts are nested two levels deep: a folder per website, and inside it a
folder per script. No scripts at the repo root, no scripts directly inside a
website folder, no shared libraries. The only top-level folder that is *not* a
website is `.dev/` — the agent workspace (see below).

```text
userscripts/
├── AGENTS.md
├── README.md
├── UNLICENSE
├── .dev/                    # agent workspace — not a website, never a script
├── <website>/
│   ├── <script-name>/
│   │   ├── README.md          # REQUIRED
│   │   └── <script-name>.user.js
│   └── <another-script>/
│       ├── README.md
│       └── <another-script>.user.js
└── <another-website>/
    └── <script-name>/
        ├── README.md
        └── <script-name>.user.js
```

### Folder naming

- **Website folder**: the site's name, lowercase, without `www.` or TLD —
  `youtube`, `github`, `reddit`. One folder per site; reuse it for every
  script targeting that site.
- **Script folder**: lowercase, hyphen-separated, describing what the script
  does — `hide-sidebar`, `wide-diff`. Do not repeat the site name; the parent
  folder already says it.
- The `.user.js` file inside uses the same name as its script folder.
- An **empty website folder** is a placeholder for a site with scripts still
  to come. It holds nothing, is not listed in the root `README.md`, and —
  since git keeps no empty folders — exists only on the machine it was made
  on; the plan itself lives in `.dev/notes/ideas.md`.

## Agent workspace: `.dev/`

`.dev/` is the one place in this repo where an agent may work freely without
asking. Use it to test changes and to keep documentation for yourself. It is
gitignored by this repo and is its own **private** git repository
(`inklikeurine/userscripts-dev`), nested inside the public one, so nothing in
it is published. What lives there:

- `tools/` — `check.mjs`, the validator that enforces every mechanical rule in
  this file; `new-script.mjs`, a scaffolder that lays down a new script from
  the templates.
- `templates/` — skeleton `.user.js` and `README.md`. **Start every new
  script from these**; do not write the metadata block or README from memory.
- `harness/` — Playwright + headless Firefox runner with a `GM_*` shim.
- `notes/` — shared knowledge: `patterns.md` (how to write a userscript that
  survives contact with a real site), `gm-api.md` (Violentmonkey API notes),
  `sites/<website>.md` (dated DOM/selector notes per site), `ideas.md`
  (planned scripts), `status.md` (where we are / what's next / waiting on
  the owner — overwritten at the end of every session). Date your entries;
  site knowledge goes stale.
- `review/` — per script, `review/<website>/<script-name>/`: `journal.md`, the
  verification journal appended to on every change, and `harness.json`, the
  saved harness invocation that backs an **Automated Test** tick
  (`node .dev/harness/run.mjs <script> --spec` re-runs it). See
  **Verification** below.
- `fixtures/`, `profiles/`, `out/` — saved page HTML, throwaway browser
  profiles, harness output. Never PII; never a logged-in page.

Rules:

- `.dev/` is **not** a website folder. Never put a userscript in it and never
  list it in the root `README.md` **Userscripts** section.
- Nothing under `<website>/` may depend on anything in `.dev/`. Scripts stay
  self-contained and installable on their own.
- The "no `package.json` / linter / CI" rule applies to the repo root and to
  script folders. Tooling inside `.dev/` may have whatever it needs.
- `.dev/` is **ignored by this repo in its entirety** (see `.gitignore`) and
  committed only to its own private repository. On a fresh clone it is absent
  until cloned in (`git clone https://github.com/inklikeurine/userscripts-dev .dev`,
  then `npm install` in `.dev/harness/`); when it is absent, every rule in
  this file still applies, done by hand.
- `.claude/settings.json` (the permission allow-list and the `PostToolUse`
  hook that runs the validator after every edit) and `CLAUDE.md` (which
  imports this file) are **committed** in the public repo, so a fresh clone
  keeps its guard rail. The hook skips quietly when `.dev/` is absent.
- The no-PII rule still applies even though the folder is untracked. Don't
  leave logged-in page fixtures or browser profiles lying around.
- Keep `.dev/README.md` current so the next agent (or human) can find things.
- **Before ending a session, overwrite `.dev/notes/status.md`** — where we
  are, what's next, what is waiting on the owner. It is how a repo gets
  picked up cold.

## Per-userscript requirements

### `README.md` (REQUIRED in every script folder)

A script folder without a `README.md` is incomplete. Never commit one. Start
from `.dev/templates/README.md`. Each README must contain:

1. **Title** — the script name.
2. **What it does** — one or two paragraphs in plain language.
3. **Where it runs** — the site(s)/URL patterns it matches.
4. **Install** — a link to the raw `.user.js` file (the `@downloadURL` from
   **Hosting and URLs**) so Violentmonkey can pick it up directly, plus a
   one-line note that Violentmonkey for Firefox is required.
5. **Notes / caveats** — anything the user should know: permissions used
   (`GM_*` grants), external requests, known breakage, site-change fragility.
6. A **Firefox only** notice: developed for Firefox and not tested in any
   other browser; other browsers unsupported.
7. An **AI-generated** notice: state that the script was generated by an AI
   agent and is used at the user's own risk.

### `<script-name>.user.js`

- Must begin with a valid userscript metadata block (`// ==UserScript==` …
  `// ==/UserScript==`). Start from `.dev/templates/script.user.js`.
- Required metadata keys: `@name`, `@namespace`, `@version`, `@description`,
  `@match` (one or more), `@grant`, `@run-at`, `@homepageURL`, `@supportURL`,
  `@downloadURL`, `@updateURL`. The URL keys take exactly the values in
  **Hosting and URLs**.
- Use `@grant none` unless a `GM_*` API is actually needed; list only the
  grants that are used. Prefer plain DOM and `localStorage` over `GM_*`
  storage. When a `GM_*` API is unavoidable use the synchronous `GM_*` form
  (Violentmonkey supports it) and name it in the README.
- Plain JavaScript, no build step, no external dependencies unless there is no
  reasonable alternative — and if one is used, declare it with `@require` and
  explain it in the README.
- Firefox only: do not rely on Chrome-only APIs or behavior. Anything that
  works only in Chromium-based browsers is a bug.
- Keep each script self-contained. Do not import from other script folders.
- Code should be readable by someone who did not write it: short functions,
  comments where the site's DOM structure is non-obvious.

### Writing the script

Structure is only half the job. AI-written userscripts fail in the same five
ways; the long version with examples is `.dev/notes/patterns.md`.

- **SPA navigation.** YouTube, GitHub, Reddit and most large sites do not
  reload the page. A script that runs once at `document-idle` works on the
  first page and never again. Use a `MutationObserver` on `document.body`
  (debounced) or the site's own navigation event (`yt-navigate-finish`,
  `turbo:load`, …) and re-apply.
- **Idempotency.** Re-running must not double-inject. Mark what you added
  (`data-<script-name>` attribute, an element `id`) and check before adding.
- **`@run-at`.** `document-start` has no DOM; `document-idle` is too late to
  prevent a flash of the thing you are hiding. CSS-only scripts:
  `document-start` + a `<style>` element. DOM-manipulating scripts:
  `document-idle` + an observer (`document-body` if the flash matters).
- **Selectors.** Sites ship obfuscated class names. Prefer `id`, `aria-*`,
  `data-*`, custom element tags, and structure over `.css-1a2b3c`.
- **Page globals.** With `@grant none` the script runs unsandboxed and
  `window` is the page's window. With any `GM_*` grant it runs in a sandbox
  and the page's globals are on `unsafeWindow` (no grant needed for it in
  Violentmonkey). Don't reach into a site's JS unless there is no DOM route.

### Versioning

`@version` uses a **Major.Minor** scheme — two numbers only, no patch
component. Minor is always at least two digits, zero-padded.

- **Major** — bump for new features or behavior changes. Reset Minor to `00`.
- **Minor** — bump for bug fixes that do not add or change features. Fixing a
  script the *site* broke is a bug fix, however large the diff.

New scripts start at `1.00`. Examples: `1.00` → bug fix → `1.01` → bug fix →
`1.02` → new feature → `2.00` → bug fix → `2.01`. Past `1.99` the next fix is
`1.100`, not `2.00` — managers compare each segment numerically, so `1.100`
sorts after `1.99`.

Every functional change to a script bumps `@version`. README-only changes do
not.

## Workflow for adding a script

0. Run `node .dev/tools/new-script.mjs <website> <script-name> "<description>"`
   if the tools exist. It performs steps 1–5 from the templates. Otherwise:
1. Create `<website>/` if it does not already exist.
2. Create `<website>/<script-name>/`.
3. Copy `.dev/templates/script.user.js` to
   `<website>/<script-name>/<script-name>.user.js`, fill in the placeholders,
   `@version 1.00`.
4. Copy `.dev/templates/README.md` to `<website>/<script-name>/README.md`
   and fill in every required section above.
5. Add the script under the correct website heading in the root `README.md`
   **Userscripts** list, creating the heading if this is the site's first
   script. If the `_No scripts yet._` placeholder is present, remove it.
6. Write the script body (see **Writing the script**).
7. Work through the **Definition of done** below and end with a
   **Verification report**.

## Workflow for changing a script

1. Make the change.
2. Bump `@version` per the Major.Minor rules above.
3. Update the script's `README.md` if behavior, matched sites, or grants
   changed.
4. If the description changed, update the entry in the root `README.md` too.
5. Work through the **Definition of done** below and end with a
   **Verification report**.

## Workflow for removing a script

1. Delete `<website>/<script-name>/`.
2. Remove its entry from the root `README.md`.
3. Remove the website's heading from the root `README.md` if it has no
   scripts left. The empty folder may stay as a placeholder for a planned
   script (see **Folder naming**) or be deleted.

## Verification

An agent in this repo has no browser. "Works in Firefox" is therefore split
into three checks. Report each one as ticked or unticked, using these exact
names, and never tick one you did not do:

- **Validated** — static checks only: layout, README sections, root README
  in sync, metadata, `node --check`. Run `node .dev/tools/check.mjs`; if
  it is absent, do every item by hand.
- **Automated Test** — the script was injected into a Firefox engine via
  `node .dev/harness/run.mjs` (if it exists) at its declared `@run-at`,
  with a `GM_*` shim honouring its `@grant` list; no uncaught errors and the
  stated effect was observed. If not run, say why. `check.mjs` accepts this
  tick only when `.dev/out/<script-name>/result.json` records a passing run
  of the current source at the current `@version`.
- **Manual Review** — real Firefox + Violentmonkey, by a human, walking the
  list in the report. An agent never ticks this.

Reaching only **Validated** is acceptable. Claiming a check you did not do
is not.

### Definition of done

A script change is done when all of these are true:

1. **Layout** — folder and file names follow the naming rules; `README.md`
   exists with all seven sections; the root `README.md` list matches the
   folders (placeholder line removed if this is the first script).
2. **Metadata** — block parses; all required keys present with the URL
   values from **Hosting and URLs**; every `@match` is a legal match
   pattern; `@run-at` is a legal value; `@grant` lists exactly the `GM_*`
   functions the body calls (`none` if it calls none); `@version` is `1.00`
   for a new script or bumped per the Major.Minor rules for a change.
3. **Syntax** — `node --check <script-name>.user.js` exits 0.
4. **Runtime** — **Automated Test** was done, **or** the report states why
   it was not (no harness, site requires login, fixture unavailable, …).
5. **Report** — the verification report below is the last thing in your
   final message, and a copy is appended under a dated heading to
   `.dev/review/<website>/<script-name>/journal.md` (create the file if
   this is the script's first change).

Items 1–3 are **Validated** — `check.mjs` exits 0 exactly when they hold.
Item 4 is **Automated Test**. **Manual Review** is deliberately not part of
done — item 5 hands it to the human.

### Verification report

Exact shape:

```markdown
## Verification — <website>/<script-name> v<Major.Minor> — <YYYY-MM-DD>

- [x] Validated
- [ ] Automated Test — not run: <reason>
      (or: [x] Automated Test — <url or fixture>, <what was asserted>,
       screenshots in .dev/out/<script-name>/)
- [ ] Manual Review

Checked by agent:
- layout, README sections, root README in sync
- metadata: keys, URLs, @match, @run-at, @grant vs. usage, @version
- node --check

Not checked — please verify in Firefox + Violentmonkey:
1. Install from <raw URL or path>. Expect: Violentmonkey shows name
   "<@name>", version <X.YY>, matches <N> pattern(s).
2. Open <url>. Expect: <the stated effect, concretely>.
3. <SPA navigation step, if the site is an SPA>. Expect: effect persists.
4. Reload. Expect: effect present, no duplicated elements.
5. Open the browser console. Expect: no errors from the script.
6. <anything specific to this change>
```

Rules for the "Not checked" list:

- Every item is a **click + expectation** pair. "Check that it works" is
  not an item.
- Items 1, 2, 5 are always present. Items 3–4 are present for any script
  that touches the DOM. Item 6 is per-change.
- Write the list from the *diff*, not from the whole script. A one-selector
  bug fix produces one or two items, not a regression suite.
- When **Automated Test** was done the list gets shorter, never empty —
  manager integration is always manual.

## Things not to do

- Do not add a `package.json`, bundler, linter config, or CI unless explicitly
  asked. This is a flat collection of standalone files.
- Do not add a license other than the Unlicense, and do not add per-file
  license/copyright headers.
- Do not create a script folder without a `README.md`.
- Do not place a script anywhere other than `<website>/<script-name>/`.
- Do not leave the root `README.md` script list out of sync with the folders.
- Do not use three-part (`x.y.z`) version numbers, or a single-digit Minor
  (`1.0`).
- Do not test in, target, or accommodate Chrome. Firefox is the only browser.
- Do not target or accommodate Tampermonkey or Greasemonkey. Violentmonkey is
  the only userscript manager.
- Do not write "tested in Firefox" about work only you have touched. Tick
  **Validated** or **Automated Test** and hand **Manual Review** to the human
  in the verification report.
- Do not store personally identifiable information (PII) anywhere in this
  repository.
- Do not collect data, phone home, or make network requests beyond what the
  script's stated purpose requires. Anything that does make requests must say
  so in its README.
